# Tau-3 Retail with FAFO

This example tenant is a reproducible recipe for using the FAFO data pipeline
evaluation-asset pipeline with the Retail domain of
[$\tau^3$-bench](https://github.com/sierra-research/tau2-bench), then optimizing
the Tau agent prompt with FAFO.

It follows the external-benchmark pattern used by `tenants/hotpotqa`: benchmark
code and data stay in their own pinned checkout, while FAFO contains the
adapter, evaluation chain, scorer, prompts, experiment protocol, and compact
history.

## Status

- Lifecycle: reproducible example tenant
- Tau release: `v1.0.1`
- Tau commit: `fc0055dc4e0a316c3f83133267fbd6faaa770992`
- Domain and split: `retail` / `base`
- Agent and user simulator: `gpt-4.1-2025-04-14`, temperature `0.0`
- FAFO rubric model used in the recorded run: `gpt-5.6-luna`
- FAFO guideline judge used in the recorded optimization: `gpt-5.5`
- Optimization scope: agent instruction prompt only

## Workflow

```text
workspace/
├── fafo/                 # this repository
└── tau2-bench/           # pinned Tau sibling checkout

Tau development tasks
  -> repeated baseline episodes
  -> one FAFO record per complete episode
  -> outcome-blind feedback sample
  -> manual trusted feedback
  -> FAFO guideline and episode-rubric generation
  -> trusted/mixed/staged prompt optimization
  -> native Tau evaluation on the sealed final holdout
```

The checked-in recipe contains no raw Tau tasks, conversations, manual
feedback, generated evaluation assets, or eval outputs. Those remain local and
are ignored by Git.

## Quick Start

Prerequisites are Git, `uv`, Python 3.12–3.13 for Tau, a FAFO-compatible
Python environment, and an OpenAI API key. The two projects keep separate
virtual environments.

From the FAFO repository root:

```bash
# 1. Create the pinned sibling Tau checkout.
python tenants/tau3_retail/scripts/setup_tau_runtime.py

# Add --use-system-truststore only if your network requires the OS trust store.

# 2. Supply the credential at run time. Never commit it.
export OPENAI_API_KEY="<your-key>"

# 3. Generate four baseline episodes for every development task.
python tenants/tau3_retail/scripts/run_tau.py \
  --partition development \
  --num-trials 4 \
  --save-to fafo_v3_development_4trials

# 4. Convert every complete Tau episode into one unlabeled FAFO record.
python tenants/tau3_retail/code/export_fafo_traces.py \
  --results ../tau2-bench/data/simulations/fafo_v3_development_4trials/results.json

# 5. Select and render the manual-feedback sample.
python tenants/tau3_retail/code/feedback_workflow.py select --count 37
python tenants/tau3_retail/code/feedback_workflow.py render

# Edit the files under source_artifacts/feedback-review/, then join them.
python tenants/tau3_retail/code/feedback_workflow.py join

# 6. Build and run the FAFO evaluation asset.
python -m hephaestus.cli assets create \
  --tenant tau3_retail \
  --asset-id fafo-v3-luna-v1 \
  --feedback tenants/tau3_retail/source_artifacts/labeled_feedback.jsonl \
  --unlabeled tenants/tau3_retail/source_artifacts/unlabeled_traffic.jsonl \
  --rubric-model gpt-5.6-luna \
  --embedding-model text-embedding-3-small \
  --clusters 50 \
  --match-threshold 0.65

python -m hephaestus.cli assets run \
  --tenant tau3_retail \
  --asset-id fafo-v3-luna-v1 \
  --rubric-model gpt-5.6-luna \
  --embedding-model text-embedding-3-small \
  --clusters 50 \
  --batch-size 3 \
  --match-threshold 0.65 \
  --min-trusted-examples 1 \
  --min-trusted-groups 1 \
  --max-unlabeled-to-trusted-ratio 20 \
  --no-synthetic-coverage \
  --split-seed 42
```

The pipeline pauses at `awaiting_review` after Stage 7. Inspect the review
snapshot and holds, then finalize with its exact review-set and decision-set
fingerprints. The detailed commands and safeguards are in the
[complete recipe](docs/recipe.md).

## Included Components

- `scripts/setup_tau_runtime.py`: pin and validate the sibling Tau checkout.
- `patches/tau3-v1.0.1-truststore.patch`: optional, version-pinned TLS patch.
- `scripts/run_tau.py`: run the frozen development or final-holdout matrix.
- `code/export_fafo_traces.py`: convert complete Tau episodes to the FAFO input
  contract without native rewards or hidden evaluator fields.
- `code/feedback_workflow.py`: select traces outcome-blind, render conversations
  for manual feedback, and produce disjoint labeled/unlabeled files.
- `chains/tau_episode.py` and `code/run_tau_episode.py`: run one fresh Tau
  episode for each FAFO evaluation case.
- `code/scorers/guideline_judge.py`: score the fresh episode against its
  case-specific FAFO rubric.
- `prompts/v3/`: exact prompt texts generated by the trusted-only, full-mixed,
  and staged optimization arms.
- `docs/iteration-memory.jsonl` and `docs/change-log.md`: compact optimization
  history and lessons.

## Data Safety

- Do not commit `source_artifacts/`, `evaluation_assets/`, `datasets/`,
  `evals/`, review files, native Tau results, or credentials.
- Do not expose the final-holdout tasks to FAFO, the rubric generator, the
  guideline judge, failure analysis, or prompt selection.
- Do not copy native reward, expected actions, database assertions, hidden user
  scenarios, or the Retail policy into FAFO input records.
- Treat the scenario-family split as experiment metadata created for this
  recipe; it is not a native Tau field.
